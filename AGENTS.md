# MASTER RULES

1. **One database only.** The only database is `mehta_electronics_local`. Never create, drop, copy or connect to any other database, test database, schema-per-test, SQLite file, in-memory database or Docker database. Schema changes are new numbered files in the existing migrations folder (next number after `0033_tally_order_lookup.sql`), applied to this database by the existing startup runner. Tests must run inside a transaction that is rolled back, or use rows tagged `ZZTEST_` that the same test removes. Never leave test data behind.
2. **One project only.** Work only inside this repository. No new repo, no microservice, no separate worker, no second backend or frontend, no cloud service, no external API URL, no new port. Keep the single listener (`src/controldesk-server.js`, normally 127.0.0.1:3000). The frontend calls relative `/api/...` only. The only other process is the existing Windows Tally connector in `connectors/tally-windows`, which talks to this app's `/api`.
3. **Out of scope (another engineer owns it).** Do not build or change email or WhatsApp intake, AI/LLM classification or extraction, Make.com flows, outbound sending, SMTP, reminders that send messages, or the automation switches. All automation switches stay OFF. Do not weaken any existing send gate or approval gate.
4. **Tally is the source of truth.** The connector stays read-only by default. ControlDesk never overwrites Tally data. Any write to Tally must go through an outbox, per-category direction config set by the owner, a dry-run mode and an idempotency key, and must be OFF by default.
5. **No invented business values.** A rule Prem has not confirmed (margin floor, credit tiers, approval levels, warranty period, reminder limits, KPI formulas, incentive formula) is a configurable value that starts empty and blocks the workflow that needs it. Never seed fake business data into `mehta_electronics_local`.
6. **Security and integrity.** Every endpoint checks session, CSRF and permission on the server. Every change writes the audit log. No hard deletes (soft delete with reason). Maker-checker: the creator cannot approve. Money uses exact decimals (decimal strings or BigInt), never JavaScript Number. No secrets in code, logs or the repo.
7. **Work method.** First read the existing code and follow its patterns (controllers, services, repositories, typed API client, shared UI components). Prefer small, focused diffs. Add tests. Do not commit unless asked. Update `docs/client-plan-implementation.md`. Never claim something works unless you ran it.
8. **Report format.** End every task with: (a) what changed, (b) files changed, (c) migrations added, (d) commands run with pass/fail, (e) what you could not verify, (f) risks and open questions.
